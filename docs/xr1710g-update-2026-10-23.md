## Merge review and corrections

- Remove four duplicate Airoha Ethernet backports now present upstream:
  shared-QDMA BQL accounting, maximum receive length, fragment DMA mapping,
  and lossless MIB statistics. Keep the upstream implementations once.
- Keep the upstream Ethernet QoS/QDMA and LRO changes. Rebase the local
  SOE packet path onto the new LRO receive path and direct PPE SRAM commit
  implementation; do not restore the older NPU SRAM-flush interface.
- Retain local PHY/PCS/PCIe, coherent NPU mailbox, recovery, and device-link
  fixes. Refresh switch, netfilter and other affected patch contexts.
- Use upstream `devm_work_autocancel()` for watchdog work initialization
  and lifetime management. Keep local recovery-status/wait helpers, without
  adding a second work initialization or cancellation action.
- Use upstream mt76 power-limit command plumbing and station link-state
  handling, while retaining the local power-path table extension.
- Preserve the per-radio transmit-power feature, including normal and OWE
  interface tracking after upstream's wireless setup refactor.
- Add a final-teardown NAPI bitmap: upstream now disables RX NAPI before
  MCU cleanup, while the local common cleanup also disables registered
  RX NAPI before page-pool destruction. A second `napi_disable()` would
  block. The new patch shares the disabled state, preserves both ordering
  requirements, and clears the marker at registration/deletion.
- Extend upstream station-event validation to recognize the local airtime
  event. Check the local per-station reply's fixed header before reading
  its station count.

The configuration still selects IPv6, odhcp6c, odhcpd-ipv6only and
`dnsmasq-full` with DHCPv6, DNSSEC, nftset and conntrack support. Commit-pinned
Actions and the existing image/DNS regression gates remain in place.

## Follow-up: mac80211 preparation failure and correction

The [initial full build at `311094a005`](https://github.com/SHD-ISAC/XR1710G-Custom/actions/runs/39839620849)
passed source downloads and all 17 mt76 regression cases, then failed while
applying `398-mtk-mac80211-fix-ieee80211_mgmt_tx.patch`. Image validation and
the built DNS/DHCP tests were skipped; that run produced no firmware artifact.

The upstream `394-wifi-mac80211-select-the-link-a-management-frame-asks.patch`
already fixes management-frame selection when a lower link shares the MLD
address, and also handles an unknown peer on an active MLD link. The older
MediaTek patch assumes the earlier function body and limits that path to a
known MLO peer. Remove the superseded local patch and retain the upstream
implementation. Bump mac80211's package release from 9 to 10.
Refresh the per-radio RTS patch's obsolete surrounding declarations and
antenna-setting context without changing its RTS update/rollback behavior.

The new preflight verifies the pinned backports archive SHA256 and applies
all 212 mac80211 patches in the 13 directories of the package's actual
`Build/Patch` sequence, requiring `patch --fuzz=0`. All patches apply
successfully without fuzz. Ten additional host-side cases compile
the actual management-frame channel-selection block and check known/unknown
MLD peers, station MLD, link source addresses, a single-link interface, missing
or unspecified channels, forced off-channel transmission and NAN scheduling.
All ten pass. The unpatched backports source fails the lower-link/MLD-address
regression, demonstrating that the test detects the behavior being preserved.

CI now runs this complete mac80211 preflight before the mt76 checks and full
compilation, and saves its log with the other build records. This extends the
previous check, which covered mt76 but omitted the complete mac80211 series.
