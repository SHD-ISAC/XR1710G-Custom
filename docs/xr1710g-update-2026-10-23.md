YYH's XR1710G port and the subsequent local regression fixes. It does not
change the XR1710G DTS, compatibility version 2.0, flash layout, port mapping,
or board initialization scripts. It does not update any bootloader.

## Merge review and corrections

- Remove four duplicate Airoha Ethernet backports now present upstream:
  shared-QDMA BQL accounting, maximum receive length, fragment DMA mapping,
  and lossless MIB statistics. Keep the upstream implementations once.
- Keep the upstream Ethernet QoS/QDMA and LRO changes. Rebase the local
  SOE packet path onto the new LRO receive path and direct PPE SRAM commit
  implementation; do not restore the older NPU SRAM-flush interface.
- Retain local PHY/PCS/PCIe, coherent NPU mailbox, recovery, and device-link
  fixes. Refresh switch, netfilter and other affected patch contexts.
- Use upstream `devm_work_autocancel()` for watchdog work initialization
  and lifetime management. Keep local recovery-status/wait helpers, without
  adding a second work initialization or cancellation action.
- Use upstream mt76 power-limit command plumbing and station link-state
  handling, while retaining the local power-path table extension.
- Preserve the per-radio transmit-power feature, including normal and OWE
  interface tracking after upstream's wireless setup refactor.
- Add a final-teardown NAPI bitmap: upstream now disables RX NAPI before
  MCU cleanup, while the local common cleanup also disables registered
  RX NAPI before page-pool destruction. A second `napi_disable()` would
  block. The new patch shares the disabled state, preserves both ordering
  requirements, and clears the marker at registration/deletion.
- Extend upstream station-event validation to recognize the local airtime
  event. Check the local per-station reply's fixed header before reading
  its station count.

The configuration still selects IPv6, odhcp6c, odhcpd-ipv6only and
`dnsmasq-full` with DHCPv6, DNSSEC, nftset and conntrack support. Commit-pinned
Actions and the existing image/DNS regression gates remain in place.

## Checks completed locally

- All 30 mt76 patches apply to the exact pinned pristine source with
  `patch --fuzz=0`.
- All 17 host-side C regression cases pass: five existing teardown/MLD
  cases, five NAPI teardown/re-registration cases, and seven valid/truncated/
  oversized-count/unknown station-event cases. The new tests compile actual
  prepared C functions or validation prefixes with controlled host stubs.
- A negative control without the new NAPI patch fails on duplicate
  `napi_disable()`, demonstrating that the added check detects this conflict.
- A focused preparation of the 85 runtime files touched by the Airoha
  patch series applies 240 relevant generic/Airoha patches. All Airoha
  hunks apply with zero fuzz. This excludes architecture, documentation,
  sound and unrelated kernel files; it is not a full kernel preparation
  or compilation test.
- Two inherited generic netfilter hunks use normal patch fuzz. Their
  resulting VLAN-passthrough and output-interface fallback code was reviewed
  in `nft_dev_forward_path()`. No Airoha-local fuzzy application is accepted.

The extended mt76 suite is invoked by the existing CI patch-check step,
so future code builds run it automatically.

## Build and hardware status

At this source commit, the new full build and image-level checks are pending.
Use the [XR1710G workflow](https://github.com/SHD-ISAC/XR1710G-Custom/actions/workflows/xr1710g.yml)
and verify its source SHA and conclusion before choosing an artifact. The
October 6 firmware's old artifacts expired on October 20 and do not validate
this update.

No physical router was available for these checks. The originally reported
no-Wi-Fi/no-DHCP boot failure was not captured with a serial log, and the
earlier AP-mode IPv6/upload stall is not proven resolved. Source regression
checks and compilation cannot guarantee successful boot or packet delivery.

After a successful build, physical checks still need to cover Ethernet/DHCP,
LuCI access, each Wi-Fi radio, IPv4/IPv6 traffic in both directions, AP/bridge
mode, and reboot/recovery. Keep a known-good rollback and confirm the flash
layout before any upgrade; do not bypass compatibility checks with `-F`.
