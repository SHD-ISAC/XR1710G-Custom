## Forward-path integration

Upstream now passes a caller-owned `net_device_path_ctx` to
`dev_fill_forward_path()`. It also introduces a stable IEEE80211 egress path
and bridge FDB/VLAN validation during flow garbage collection, addressing
stale offloaded forwarding after a client moves between ports.

- Remove the superseded local `__dev_fill_forward_path()` export/wrapper.
  Keep the bridge FDB export required by the local bridging support.
- Adapt bridging to the public context API, preserving caller-supplied VLAN
  and flow keys. Set `ieee80211` for the flowtable path; leave it clear for
  Airoha's driver-specific WDMA lookup.
- Keep bonding's immutable flow keys in the context. The previous unused
  `dev_fill_forward_path_flow()` wrapper is unnecessary with the public API.
- Update the local WLAN bridge-subflow fallback to the new two-argument
  API. Ask for the stable IEEE80211 egress device, then resolve WDMA through
  entry preparation. This avoids conflating bridge egress with hardware
  station lookup and eliminates an otherwise uncompilable legacy call.
- Preserve upstream bridge-path/VLAN flags alongside the local XFRM/SOE
  xmit-type guard. Keep the existing FDB-deletion notifier: upstream's new
  GC check covers FDB moves and VLAN state, while this notifier handles
  deletion events. Neither implementation replaces the other.
- Refresh the VLAN passthrough, output-ifindex fallback and affected patch
  contexts. Bump mac80211 from local r10 to r11 because upstream also moved
  to r10 with additional changes.
