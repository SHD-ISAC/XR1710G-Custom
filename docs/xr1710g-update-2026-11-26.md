# XR1710G source update: November 26, 2026

Merged 389 commits from OpenWrt main since the November 7 update, through
[`f76496253d`](https://github.com/openwrt/openwrt/commit/f76496253dfc6a987843a32c5f18b92f668dd3e0).
Linux goes from 6.18.60 to 6.18.64. The
[packages feed](https://github.com/openwrt/packages/commit/a3cc8482f4037f118bc135cfca191c7cb6250aa6)
and [LuCI feed](https://github.com/openwrt/luci/commit/8d1aecd0216a02ad52c830e9a03c21da734bf630)
have new fixed commits. The routing feed and mt76 source stay pinned to the
previous commits. mac80211 still uses backports 7.2; this fork's package
release is 19, including its wireless patches. The device config still
selects `dnsmasq-full` with DNSSEC and IPv6.

## Upstream support and upgrade compatibility

OpenWrt merged initial XR1710G support in
[PR #26296](https://github.com/openwrt/openwrt/pull/26296) on November 24.
Its DTS and this fork both place the read-only vendor data at
`0x000000–0x600000`, the read-only chainloader at `0x600000–0x700000` and
UBI at `0x700000–0x1be00000` (end offsets exclusive). The factory and MAC
offsets are preserved. The two images use different interface names and
device-specific settings:

| Setting | This fork | OpenWrt main |
| --- | --- | --- |
| WAN interface | `eth1` | `wan` |
| LAN bridge ports | `eth2 lan2 lan3` | `lan2 lan3 lan4` |
| Sysupgrade metadata compatibility | 2.0 | 1.0 (default) |

This fork retains its DTS, compatibility marker, and supported-device alias.
Preserving settings across builds of this fork does not imply that the
official image can read and use the same port configuration. The workflow
produces a sysupgrade and recovery image; it does not package an XR1710G
chainloader.

The upgrade checks the FIT and preserves a valid existing factory UBI volume.
If the volume is missing or invalid, it reads the calibration and MACs from
the vendor partition and validates them before writing the factory volume.
Incorrect device identification, incomplete calibration reads, and factory
write failures stop the upgrade before the firmware FIT is written. This
incorporates the stricter recovery handling from
[YYH's implementation](https://github.com/YYH2913/openwrt/commit/fa9f7d548117f0e85c4178d8d89422672a75b5b4)
alongside the upstream
[short-read correction](https://github.com/openwrt/openwrt/pull/26928).
The later YYH mt76, NPU and PHY experiments were left out of this update.

A clean setup no longer sets a common root password or enables open Wi-Fi
networks. The board also stops forcing the US regulatory domain, specific
channels, and 160/320 MHz widths during first boot after sysupgrade.
Previously the first-boot script ran after the Wi-Fi configuration had been
restored and rewrote those settings. Retained radios now keep their
configured country, channel and width. If starting with a clean configuration,
use wired LAN to set a password, select the country where the device is
operated, and enable Wi-Fi with the desired security settings.

## Follow-up: firewall4 build failure

[Run 45785576637](https://github.com/SHD-ISAC/XR1710G-Custom/actions/runs/45785576637)
stopped before image generation: upstream firewall4 changed its
lower-device resolver, invalidating the fork's bonding patch. The patch now
uses the common bridge/VLAN traversal and carries upstream's wireless port
prefix handling through bonded links. Both the source pin and the firewall
feature set are retained. CI checks the patch against the pinned firewall4
source before starting the full build.

## Validation

On the host, the kernel patch stack applied and both wireless patch stacks
applied without fuzz. The 55 host-side behavioral checks covered mac80211
(10), mt76 (18), Wi-Fi forwarding (7), Netfilter forwarding (9), and simulated
FIT upgrade and factory calibration handling (11). The last test group
also runs in CI before compiling the firmware.

Full build, artifact inspection, and physical-device results are tracked
separately from host-side patch and behavior checks. A successful source
build alone does not establish that LAN/DHCP, Wi-Fi and IPv6 work on a
physical XR1710G.
